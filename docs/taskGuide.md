# Task Guide — Salary простыми словами

> Это тот же план, что в `tasks.md`, с той же нумерацией, но без технического жаргона.
> Чтобы было понятнее, представим, что мы **строим и обставляем небольшой магазин**:
> сначала готовим инструменты и участок, потом фундамент, стены, двери с замками, витрины — и только потом открываемся.

## Мини-словарик

| Слово                 | Что это на самом деле                                                                                          |
| --------------------- | -------------------------------------------------------------------------------------------------------------- |
| **Приложение / сайт** | Программа, которая открывается в браузере (Chrome, Safari) по ссылке                                           |
| **Next.js**           | Готовый «конструктор» для сборки сайтов: в нём уже есть стены и проводка, мы только расставляем мебель         |
| **Код**               | Текстовые инструкции для компьютера, как рецепт для повара                                                     |
| **База данных (БД)**  | Электронный шкаф с ящиками, где хранятся все записи: пользователи, траты, категории                            |
| **Сервер**            | Компьютер в интернете, который хранит шкаф и отвечает на запросы сайта                                         |
| **Git / GitHub**      | «Машина времени» для кода: сохраняет каждую версию, можно вернуться назад. GitHub — облако для этих сохранений |
| **Тест**              | Маленькая программа-проверяющий, которая сама нажимает кнопки и проверяет, что всё работает                    |
| **Деплой**            | Выкладывание сайта в интернет, чтобы им могли пользоваться другие                                              |

---

## Шаг 1. Готовим инструменты и рабочее место

- **1.1** Устанавливаем на компьютер программы, без которых нельзя начать: «двигатель» для запуска кода (Node.js), «машину времени» (Git) и удобный редактор, в котором пишут код (VS Code). Как купить молоток, дрель и верстак перед стройкой.
  ✅ _Как понять, что готово:_ программы установлены и отвечают, когда к ним обращаешься.
- **1.2** Создаём пустую заготовку будущего сайта одной командой. Это как получить коробку с каркасом домика: стены уже стоят, но внутри пусто.
  ✅ В браузере по адресу `localhost:3000` открывается стартовая страница — это наш сайт, пока видимый только на нашем компьютере.
- **1.3** Включаем «автоматического уборщика»: он будет сам выравнивать и проверять код перед каждым сохранением, чтобы всё было аккуратно и одинаково оформлено.
  ✅ Неаккуратный код исправляется сам.
- **1.4** Создаём «облачный сейф» для кода на GitHub и кладём туда первую версию. Если компьютер сломается — ничего не потеряется.
  ✅ Код виден на сайте GitHub.
- **1.5** Ставим на свой компьютер тренировочную базу данных — «шкаф для записей», с которым можно экспериментировать, ничего не ломая по-настоящему.
  ✅ Шкаф включён и готов принимать записи.
- **1.6** Заводим отдельный файл для секретов (пароли от базы, ключи от Google) и запрещаем ему попадать в облако. Как хранить ключи от квартиры не на двери, а в кармане.
  ✅ Секреты остаются только на нашем компьютере.

## Шаг 2. Выбираем «стиль ремонта» (дизайн-система)

- **2.1** Подключаем шрифт Inter — тот, которым будут написаны все тексты и суммы. Настраиваем так, чтобы все цифры были одной ширины и суммы в столбик стояли ровно.
- **2.2** Записываем в одно место все цвета приложения: зелёный для доходов, коралловый для расходов, цвета фона и текста — отдельно для светлой и тёмной темы. Как палитра красок, из которой берём краску при покраске любой стены.
- **2.3** Делаем фирменный «стеклянный» эффект: карточки, сквозь которые слегка видно размытый цветной фон, как матовое стекло. И запасной вариант для старых телефонов, которые так не умеют.
- **2.4** Берём набор готовых деталей интерфейса (кнопки, поля ввода, окна, выпадающие списки) и перекрашиваем их в наши цвета и скругления. Как купить мебель в IKEA и покрасить в свой цвет, вместо того чтобы пилить доски самим.
- **2.5** Добавляем переключатель «светлая / тёмная тема», который по умолчанию подстраивается под настройки телефона или компьютера.
- **2.6** Составляем список из 8 цветов и ~60 картинок-иконок, из которых пользователь будет выбирать оформление своих категорий («тележка» для продуктов, «машина» для транспорта).
- **2.7** Делаем скрытую «витрину-образец», где все детали интерфейса выставлены рядом, — чтобы одним взглядом проверить, что всё выглядит красиво в обеих темах.
  ✅ _Готово, когда:_ все элементы выглядят как в `design.md`.

## Шаг 3. Строим «шкаф для данных» (база данных)

- **3.1** Рисуем чертёж шкафа: какие в нём ящики (пользователи, счета, категории, операции, бюджеты) и что лежит в каждом (например, у операции — сумма, дата, категория, комментарий).
- **3.2** По чертежу собираем настоящий шкаф в базе данных.
  ✅ Ящики появились, их можно открыть и посмотреть.
- **3.3** Делаем так, чтобы сайт подключался к шкафу одним аккуратным «проводом», а не плодил сотни лишних подключений.
- **3.4** Учим приложение правильно считать деньги. Компьютеры плохо считают копейки в дробях (иногда 0,1 + 0,2 у них = 0,30000000004), поэтому храним всё в копейках целыми числами и пишем проверки, что расчёты точные.
  ✅ Все проверки пройдены, ни одна копейка не теряется.
- **3.5** Заполняем шкаф «демо-данными» — выдуманным пользователем с покупками за год, чтобы было на чём проверять графики.

## Шаг 4. Ставим двери и замки (вход в аккаунт)

- **4.1** Подключаем готовую «систему охраны», которая помнит, кто вошёл в приложение.
- **4.2** Делаем регистрацию и вход по почте и паролю. Пароль хранится не в открытом виде, а в виде «отпечатка», по которому его невозможно восстановить — даже мы его не узнаем.
- **4.3** Добавляем кнопку «Войти через Google» — для тех, кто не хочет придумывать пароль.
- **4.4** Рисуем красивые страницы входа и регистрации в нашем стеклянном стиле, с понятными подсказками при ошибке («Пароль слишком короткий»).
- **4.5** Ставим «охранника на входе»: незнакомца отправляет на страницу входа, а новичка — сначала на знакомство с приложением (онбординг).
- **4.6** Защита от взлома подбором: после 5 неверных паролей подряд вход временно блокируется.
  ✅ _Готово, когда:_ можно зарегистрироваться, войти и выйти, а без входа внутрь не попасть.

## Шаг 5. Строим «коридоры и стены» (каркас приложения)

- **5.1** Делаем общую «рамку» для всех внутренних страниц: фон, отступы, проверку входа. Все комнаты будут в одном здании и одном стиле.
- **5.2** Боковое меню для компьютера: Дашборд, Операции, Категории, Аналитика, Бюджеты, Настройки. На планшете оно сужается до одних иконок.
- **5.3** Нижняя панель для телефона — как в привычных мобильных приложениях, с большой круглой кнопкой «+» по центру для быстрого добавления траты.
- **5.4** Переключатель периода: «неделя / месяц / квартал / год / свой период» и стрелки «назад / вперёд». Выбранный период запоминается в ссылке — её можно отправить кому-то, и он увидит то же самое.
- **5.5** Продумываем, что видит человек, пока страница грузится (серые «заглушки» вместо белого экрана), если что-то сломалось (понятное сообщение) и если данных ещё нет (подсказка, что сделать).

## Шаг 6. Знакомство с новым пользователем (онбординг)

- **6.1** Первый экран: «В какой валюте вы считаете деньги?» (рубли, доллары, сумы и т. д.).
- **6.2** Второй экран: предлагаем готовый набор категорий (Продукты, Транспорт, Зарплата…), ненужные можно убрать галочкой.
- **6.3** Третий экран: «Где лежат ваши деньги?» — создаём первый счёт (например, «Карта») и сколько на нём сейчас.
- **6.4** Сохраняем всё разом и ведём на главный экран.
  ✅ _Готово, когда:_ новичок за минуту проходит 3 шага и видит свой дашборд.

## Шаг 7. Категории и счета

- **7.1** Учим приложение доставать из шкафа список категорий и счетов, а для каждого счёта — считать, сколько на нём денег сейчас.
- **7.2** Учим добавлять, переименовывать, прятать в архив и объединять категории и счета. И главное — проверять, что человек меняет **только свои** данные, а не чужие.
- **7.3** Делаем окошко создания категории: вводишь название, выбираешь картинку и цвет, сразу видишь, как это будет выглядеть.
- **7.4** Страница «Категории» с двумя вкладками — для расходов и доходов. Если в категории уже есть траты, удалить её просто так нельзя: приложение предложит перенести траты в другую категорию, чтобы ничего не потерялось.
- **7.5** В настройках — список счетов (карта, наличные, копилка) с текущими остатками.

## Шаг 8. Главное — доходы и расходы

- **8.1** Пишем «правила» для операции: сумма больше нуля, категория выбрана, комментарий не длиннее 200 символов. Одни и те же правила проверяются и на экране, и на сервере.
- **8.2** Учим сервер добавлять, изменять и удалять операции. Удаление «мягкое»: запись сначала кладётся в «корзину», чтобы её можно было вернуть.
- **8.3** Делаем форму добавления: сверху переключатель «Расход / Доход», большое поле для суммы, сетка категорий-иконок, дата (по умолчанию — сегодня), счёт и комментарий. На компьютере это окно по центру, на телефоне — выезжающая снизу шторка.
  ✅ Трату можно записать за 5–7 секунд.
- **8.4** Форму можно открыть откуда угодно: кнопкой «+» или клавишей `N` на клавиатуре.
- **8.5** Страница «Операции» — список всех трат и доходов, сгруппированный по дням («Сегодня», «Вчера», «12 ноября») с итогом за каждый день. Подгружается порциями, чтобы не тормозить.
- **8.6** Фильтры и поиск: показать только расходы, только «Кафе», только за прошлый месяц, суммы больше 1000 и т. д.
- **8.7** Мгновенная реакция: после нажатия «Сохранить» операция сразу появляется в списке, не дожидаясь сервера. После удаления всплывает подсказка «Удалено · Отменить». На телефоне операцию можно смахнуть влево, чтобы удалить или изменить.

## Шаг 9. Главный экран и графики (дашборд)

- **9.1** Учим базу данных быстро считать итоги: сколько пришло и ушло за период, как менялся баланс по дням, на какие категории ушло больше всего денег.
- **9.2** Четыре карточки сверху: **Баланс**, **Доходы**, **Расходы**, **Сколько % удалось отложить**. В каждой — сумма, стрелочка «больше/меньше, чем в прошлом месяце» и маленький мини-графичек. Цифры красиво «набегают» при открытии.
- **9.3** Главный график — плавные линии доходов (зелёная) и расходов (коралловая) с полупрозрачной заливкой под ними. Можно переключиться на линию общего баланса. При наведении пальцем или мышкой — всплывает подсказка с точными суммами за день.
- **9.4** Круговая диаграмма-«бублик»: какую долю расходов занимает каждая категория, а в центре — общая сумма.
- **9.5** Блок с пятью последними операциями и ссылкой «Смотреть все».
- **9.6** Расставляем всё по экрану: на компьютере — в несколько колонок, на телефоне — одной лентой. Карточки плавно появляются по очереди.
  ✅ _Готово, когда:_ главный экран открывается меньше чем за секунду даже при тысячах записей.

## Шаг 10. Аналитика — «куда ушли деньги?»

- **10.1** Учим считать сравнение по месяцам за полгода или год и средние траты в день.
- **10.2** Столбчатый график: для каждого месяца два столбика рядом — доход и расход. Сразу видно, в каком месяце «ушли в минус».
- **10.3** Рейтинг категорий: полоски от самой затратной к наименьшей. Нажал на «Кафе» — открылся список всех трат в кафе.
- **10.4** Готовые выводы человеческим языком: «В среднем вы тратите 2 300 ₽ в день», «Самый дорогой день — 3 ноября», «На кафе потрачено на 18% больше, чем в прошлом месяце».

## Шаг 11. Бюджеты — лимиты на категории

- **11.1** Учим сохранять лимиты («не больше 10 000 ₽ на кафе в месяц») и считать, сколько уже потрачено.
- **11.2** Страница «Бюджеты»: полоска заполнения для каждого лимита — зелёная, пока всё хорошо; жёлтая, когда потрачено 80%; красная, если лимит превышен. Подпись: «Осталось 2 000 ₽ на 9 дней».
- **11.3** Напоминания: если после новой траты лимит почти исчерпан — приложение вежливо предупредит, а на главном экране появится заметка.

## Шаг 12. Настройки и перенос данных

- **12.1** Страница настроек: имя, валюта, часовой пояс, тема оформления.
- **12.2** Кнопка «Скачать мои данные» — выгружает операции в файл-таблицу (CSV), который открывается в Excel.
- **12.3** Загрузка данных из файла: например, выписки из банка. Приложение покажет первые строки, спросит, какая колонка — сумма, а какая — дата, и аккуратно всё перенесёт.
- **12.4** Кнопка «Удалить аккаунт» — стирает все данные навсегда. Чтобы не нажать случайно, нужно ввести свою почту для подтверждения.

## Шаг 13. Проверяем качество

- **13.1** Пишем автоматические проверки для «мозгов» приложения: правильно ли считаются деньги, периоды, файлы.
- **13.2** Проверяем самое важное для безопасности: пользователь А **никак** не может увидеть или изменить данные пользователя Б.
- **13.3** «Робот-тестировщик» сам проходит весь путь живого человека: регистрируется, добавляет зарплату и покупку, смотрит графики, ставит бюджет, скачивает файл — и на компьютере, и в размере телефона.
- **13.4** Проверяем удобство для всех: можно ли пользоваться только клавиатурой, хорошо ли читается текст на стеклянном фоне, озвучивает ли программа для незрячих кнопки и графики, не мешают ли анимации людям, которые их отключили.
- **13.5** Измеряем скорость специальным инструментом Google (Lighthouse) — оценка должна быть 90 из 100 и выше.
- **13.6** Настраиваем «автоматического контролёра» на GitHub: при каждом изменении кода он сам запускает все проверки и не даст выпустить сломанную версию.

## Шаг 14. Открытие!

- **14.1** Арендуем «настоящий шкаф» — базу данных в интернете (Neon), а не на своём компьютере.
- **14.2** Выкладываем сайт в интернет через сервис Vercel и передаём ему секретные ключи.
- **14.3** Сообщаем Google настоящий адрес сайта, чтобы кнопка «Войти через Google» работала у всех.
- **14.4** Делаем главную страницу-витрину для новых людей: что умеет Salary, красивые скриншоты и кнопка «Начать бесплатно».
- **14.5** Последняя проверка на «живом» сайте: регистрируемся, добавляем трату, смотрим графики. Включаем защитные настройки и — запускаем версию 1.0.
  ✅ _Готово, когда:_ любой человек может открыть ссылку, зарегистрироваться и начать вести свои финансы.
